# Research Contract v0

This file defines the semantics that must be frozen before evaluating strategy performance. Changes after outcome inspection require a new contract version and explicit reason.

## Canonical timestamps

- `source_event_time`: timestamp associated with the source wallet action as reported by the underlying public data source.
- `first_observed_time`: first wall-clock time SmartCopy actually observed that source action.
- `decision_time`: time the deterministic decision engine emitted COPY/WATCH/SKIP.
- `order_send_time`: time a hypothetical or real order would be sent.
- `follower_fill_time`: time a simulated or real follower fill occurs.

Hard rule:

`first_observed_time >= source_event_time`

Backtests may not act before `first_observed_time`.

## Canonical prices

- `source_price`: price attributable to the source action/fill cluster.
- `observed_bid`, `observed_ask`: executable top of book visible at/after first observation.
- `follower_limit_price`: maximum/minimum price allowed by the decision engine.
- `follower_fill_price`: conservatively simulated or real execution price.

Midpoint is descriptive only and cannot be used as assumed execution.

## Source intent

A source intent is a deterministic cluster of related public fills/activity representing an exposure decision, not an individual fill. Intent classes:

- ENTER
- ADD
- HOLD
- REDUCE
- EXIT
- FLIP
- HEDGE
- UNKNOWN

`UNKNOWN` and unresolved hedge/arbitrage behavior are not copyable.

## Independent decision episode

Multiple source fills or repeated public updates generated by the same underlying exposure change count as one decision episode. Evaluation sample size must use independent episodes as the primary unit, not raw messages/fills.

## Source return

Return attributable to the reconstructed source decision under a documented exit/resolution convention. It is a reference metric, not follower performance.

## Follower return

Return from the follower's realistically observable and executable entry, including applicable fees, spread, slippage, partial-fill assumptions and exit costs.

## Residual Edge

Residual Edge is the estimated net advantage remaining for the follower after the source action becomes observable.

Conceptually:

`ResidualEdge = expected_value_after_observation - follower_execution_costs - risk_reserve`

This is an estimated research quantity, not ground truth. Every implementation must state exactly how expected value and costs are estimated.

## Edge decay

For each wallet x strategy class, measure follower performance as observation/execution delay increases. Delay buckets must be frozen before outcome inspection. If a bucket cannot be resolved from timestamps/data cadence, mark it `NOT_RESOLVABLE`; do not interpolate synthetic states.

## Fees and execution

Use current verified fee semantics for the market family being evaluated. Fee schedules are versioned inputs, not constants embedded without provenance.

Execution modeling must include, where applicable:

- actual bid/ask
- visible depth
- spread
- taker/maker status
- fee
- slippage
- partial fills
- order TTL
- queue/fill uncertainty
- adverse-selection reserve

## BlindCopy benchmark

BlindCopy is the mandatory baseline. Its contract must use the same public observability constraints and execution model as SmartCopy; it differs only by decision filtering.

## Matched control

Where feasible, include a matched random/non-source control with similar market family, price region, liquidity regime and time exposure. Controls must not be deliberately unrealistic.

## Data splitting

Prefer chronological discovery/evaluation separation. Never random-split adjacent events from the same intent episode across discovery and holdout.

## Prohibited research behavior

- future leakage
- entering at source price when not observable
- midpoint fills
- optimizing many thresholds on the evaluation set
- changing latency buckets after seeing results
- relabeling hedges as directional to improve performance
- dropping losing wallets/trades after outcome inspection without predeclared criteria
- counting raw fills as independent samples

## Primary project hypothesis

`SmartCopy net expectancy > BlindCopy net expectancy on unseen data under identical observability and execution assumptions.`

## Live authorization gate

Positive PnL alone is insufficient. Before live capital:

1. positive net expectancy out of sample
2. SmartCopy > BlindCopy
3. performance not dominated by one event
4. sufficient independent episodes
5. acceptable drawdown
6. edge survives measured observation latency
7. execution assumptions validated in live paper/shadow mode

Failure of any mandatory gate means `NO_LIVE`.
