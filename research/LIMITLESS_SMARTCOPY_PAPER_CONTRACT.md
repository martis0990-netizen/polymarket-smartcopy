# Limitless SmartCopy: экономический контракт v0

Дата фиксации: 2026-10-03. Статус: SPECIFIED_BUT_BLOCKED; только read-only исследования. Это отдельный контракт SmartCopy кошельков. Он не меняет исходный недельный feasibility gate, фиксированный список трёх кошельков или hourly paper experiment.

## Что уже можно измерять

Единица наблюдения — каноническая запись BUY конкретного кошелька, а не независимое намерение. Отчёт отдельно показывает FIXED_COHORT и DISCOVERY_FEED. Исторический backfill не превращается в свежий сигнал. Первый запрос стакана после обнаружения, включая ошибку, окончательный: повторные лучшие котировки не подставляются.

`entry_eligibility.data_qualified_quote` требует валидного времени, известной стороны, непротиворечивого первого наблюдения, первой котировки с достаточной видимой глубиной на 10 USDC, prospective metadata с привязкой slug/condition/YES/NO/Base USDC/6 decimals/expiry и сохранённого текста правил. Получение metadata добавляет задержку: request/receipt фиксируются, старые и новые фазы анализируются отдельно. Кэш точного slug действует только в пределах одного сегмента; проверки времени истечения выполняются для каждой котировки. Нет гарантии свежести matching-engine book или неизменности правил между запросами.

Это техническая пригодность котировки. COPY в текущем коде всегда SKIP; fill и copy_pnl — null.

## Блокирующие входные данные

До запуска экономической проверки необходимы:

1. Проспективно подтверждённый источник сигнала: intent, исходный инвентарь и стратегия; одиночный BUY из неполной истории этого не доказывает.
2. Метод fair probability `p`, версия и доступные на момент решения признаки; выбор метода и калибровки зафиксирован до оцениваемой выборки.
3. Проверенная применимая комиссия follower и её способ начисления. Boolean `metadata.fee` не задаёт размер комиссии. Текущие 3% — допущение диагностики, не проверенная комиссия кошелька.
4. Проверенные правила settlement и источник итогового outcome. Сохранённый текст и его SHA256 не означают проверенного oracle semantics.

До появления этих данных запрещено записывать гипотетический выигрыш по цене источника или считать depth walk исполнением.

## Контракт будущей paper-сделки

| Поле | Фиксированное правило |
|---|---|
| Размер | 10 USDC максимальных затрат на условие; дополнительные fills не создают новые независимые сделки |
| Повторные входы | Один первый intent на wallet+condition+side; конфликт сторон, неизвестный intent или инвентарь → SKIP |
| Решение | Только после first_observed_at; все features и параметры имеют observed_at не позже decision_at |
| Max price | При комиссии в доле полученных контрактов `f`: p_max = p × (1−f) / 1.03; при другом механизме комиссий формула требует новой заранее зафиксированной версии |
| Исполнение | Отдельный prospective snapshot после подтверждённой задержки исполнения; не старый diagnostic book. Первый eligible attempt, не лучший повтор; deadline 30 s после решения |
| Отказ | Любой unknown fee/intent/rules/probability, expired market, отсутствующая глубина до p_max, timeout → SKIP с причиной |
| Частичное исполнение | В v0 не моделируется: недостаточная глубина → SKIP; реальные частичные fills требуют отдельной модели |
| Выход | Держать до verified settlement; не копировать SELL без отдельного заранее принятого exit contract |
| PnL | USDC выплаты минус все затраты; unsettled, unverified resolution и отсутствующие данные остаются pending/unknown |
| Независимость | condition и часовой кластер; сделки двух кошельков в одном условии не считаются независимыми |

Запас 3% в знаменателе — заранее выбранное требование к gross return при модели contract-fee, а не утверждение о доступном edge. Этот контракт пока не вооружает simulator: метод p и подтверждение intent отсутствуют. Они должны быть опубликованы отдельной версией ДО будущего evaluation window. Discovery 3–5 октября не может стать holdout после просмотра результатов; для ещё не определённого wallet model окно holdout начинается только после его фиксации, даже если это позже 6 октября.

## Контроли и критерий результата

На одной и той же доступной выборке и с одинаковой задержкой, комиссией, бюджетом и settlement показывать: NO_TRADE, blind copy первого подтверждённого intent (max price = source gross price; missing source price → SKIP), будущий residual-value filter. Источник не считается источником доходности сам по себе. Blind copy — paper control, не разрешение исполнения.

Публиковать все skip reasons, размер полного denominator, число пригодных котировок, число подтверждённых intents, число settled conditions, покрытие и концентрацию по часам/кошелькам. Минимальный размер выборки и статистический тест для новой wallet-модели должны быть зафиксированы вместе с её версией до её holdout; исходные 60 proxy episodes не заменяют эту процедуру. Пока этой версии нет, economic verdict = NOT_TESTABLE, а не profitable/unprofitable.

## Сохранение и приёмка

Raw observer ZIP, manifest run/SHA/artifact, SHA256 и время snapshot сохраняются отдельно от отчёта. Пропущенные/незавершённые runs отражаются в manifest. PR-smoke данные не включаются в основную выборку. Новые artifacts хранятся 90 дней; старые 14-дневные artifacts нужно отдельно скачивать до истечения.

Приёмка automation: завершившийся main observer → artifact с raw observations/books/metadata → успешный explicit dispatch progress audit → aggregate manifest с этим artifact. Успешный PR run не заменяет эту проверку цепочки main. Для discovery отдельно проверяется main capture → main discovery с raw history/action traces. Live-торговля остаётся за пределами этого контракта.
